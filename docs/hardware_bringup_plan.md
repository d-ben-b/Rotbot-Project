## 3. 現在就能測（不必等整台機器人）——縮短之後的整合時間

| 項目 | 做法 | 省下什麼 |
|---|---|---|
| **A. 真實影像 @ 6 m**（最重要） | 用紙板/珍珠板做**等比例孔板**（至少 3×3 個 Ø40、欄距 90 / 列距 60，上排 Ø20 + 紅色 LED 燈條），貼牆；Orin + 實際相機在 4/6/7.5 m、左右偏角拍；`tools/capture_dataset.py --prelabel models/grid_holes_yolo11n.pt` 收 100–300 張 | 提早發現合成→真實落差；修正預標註後**微調 20–30 epochs（幾分鐘）**，不用到比賽才重訓 |
| B. 紅色 LED 燈環 | 買規格相近的紅色燈條（寬 ~14 mm、~475 lm）裝在 Ø20 環上，測不同曝光下亮孔辨識 | 亮孔是加分與同分第一順位，最不能錯 |
| C. 相機參數入檔 | 10 月標定的 K、畸變、解析度填進 `configs/field.yaml` `camera` 區；鎖曝光/白平衡 | 感知幾何直接用真參數 |
| D. Orin 環境與延遲 | Orin 上裝環境、`python -m tools.bench_pipeline --export-trt`（TensorRT FP16） | 確認延遲預算；引擎只能在 Orin 上產生 |
| E. Arduino 單板 + 馬達上桌 | 燒錄 `firmware/rotbot_mcu`，跑 H1、H2（無機構也能測方向/步數）；接 Orin 再跑一次 | 機構裝好當天就能動 |
| F. **飛輪試驗台** | 先把兩顆飛輪馬達 + 摩擦輪固定在板子上，量 PWM→轉速→球速（慢動作）、電池電壓影響 | **6 m 的成敗**：10 m/s 打不到上排；要不要換馬達/驅動板要現在決定 |
| G. 路由器 | Orin 上 `python -m tools.teleop_web --mcu sil --camera sim`，筆電經路由器連線測延遲 | 通訊硬體 11/9 前定案 |
| H. 打牆擬合演練 | 飛輪試驗台能出球後，用 `fit_ballistics.py` 走一次流程 | 練習日只要 30 分鐘就拿到 v0/Cd |

## 4. 軟體還缺什麼（依優先順序）

1. **真實參數入檔**（硬體組給數字即可，程式不用改）：`config.h` 的步數比/角度上下限/腳位/`FLY_MAX_RPM`；`robot.yaml` 尺寸；`field.yaml` 的 `launch_h`。
2. **落點量測**（線上校正的輸入）——模擬顯示的優先順序：
   - 飛輪轉速穩在 ±1% 時，**只用賽前練習學到的校正、比賽中不更新**，成績與線上校正相同（49.0 vs 48.6 分）。
   - 練習→比賽 v0 漂移 2–3% 時，凍結校正掉到 45.6 / 39.5 分（變異很大），線上校正仍有 ~48 分。
   - → 先做 **(a) 練習時的落點記錄**（手機慢動作或操作手在畫面上標記 → 寫進 `fit_ballistics` CSV / 校正器），
     再做 **(b) 比賽中自動判斷**（看網袋裡的球、或 60 fps 以上追球）當保險。
3. **掃視姿態搜尋**：目前假設開機時網板在預設掃視角度附近；擺偏時要能左右掃找板（或第一次手動對準再 `ZERO`）。
4. **Orin 開機自動啟動**（systemd）+ 開始方式（網頁「開始」= 規則允許的遙控器啟動）。
5. 下半場：18 球、連線加分（斜線 8 / 垂直 4 / 水平 2）的選孔策略、對手球顏色不同。

## 5. 怎麼避免「硬體接上後才重訓 / 重調」

- **幾何與物理都在設定檔**：網板尺寸、距離、相機、v0、Cd 改 YAML；韌體參數改 `config.h`。程式不動。
- **物理不用訓練**：瞄準是含阻力的物理模型，參數用 `fit_ballistics.py` 從 20–30 球擬合出來（自我驗證：v0 誤差 < 0.3 m/s）。
- **YOLO 不從零訓練**：已用 2.5–7.5 m、紅燈環、強域隨機化的合成資料訓練；真實影像只做**微調**（起點 `models/grid_holes_yolo11n.pt`）。現在就用自製孔板收實拍（§3 A），練習日再補 50–100 張。
- **校正可存檔**：練習日學到的手感 `AdaptiveCalibrator.save()` → 比賽 `--calib` 載入（模擬：從零開始 47.3 分 → 暖機 48.6 分；加分孔 21% → 30%）。
- **同一套測試從模擬一路用到實機**：`mcu_link_test`（SIL → 單板 → Orin）、`run_autonomous`（孿生 → 真轉塔+孿生 → 整機），每一步都知道是哪一層壞掉。
