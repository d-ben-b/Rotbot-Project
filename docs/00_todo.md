# 我要做什麼（照順序做）

2026-10-31 版。每一步都寫了「怎麼做」和「看到什麼就算成功」。
要確認軟體本身對不對，看另一份：[怎麼確認軟體是對的](00_verify.md)。

指令都在專案資料夾的終端機執行，先啟動環境：電腦上 `.venv\Scripts\activate`；Jetson 上把 `python` 換成 `python3`。

## 1. 把韌體燒進 MCU（NUCLEO-G474RE）

只要一條 USB 線，接板子上方 ST-LINK 那一端的 USB 孔，不用接任何馬達。
韌體是用 Arduino 寫的，用 ST 官方的 Arduino 核心（STM32duino）編譯。

1. 安裝 Arduino IDE 2，在「檔案 → 偏好設定 → 其他開發板管理員網址」貼上：
   `https://github.com/stm32duino/BoardManagerFiles/raw/main/package_stmicroelectronics_index.json`
2. 「工具 → 開發板 → 開發板管理員」搜尋 STM32，安裝 **STM32 MCU based boards**（STMicroelectronics）。
3. 打開 `firmware/rotbot_mcu/rotbot_mcu.ino`。同一個資料夾裡的其他檔案會一起編譯，不要搬動。
4. 選板子和埠：
   - 「工具 → 開發板 → STM32 MCU based boards」選 **Nucleo-64**。
   - 「工具 → Board part number」選 **Nucleo G474RE**。
   - 其他選項維持預設，上傳方式是 Mass Storage，不用另外裝軟體。
   - 「工具 → 連接埠」選 STMicroelectronics STLink Virtual COM Port 那個（這台電腦目前是 COM5；換電腦或換 USB 孔可能會變）。
     裝置管理員裡沒有這個 COM 埠的話，安裝 ST 的 ST-LINK 驅動（STSW-LINK009）。
5. 按左上角的「→」上傳。
   - ✅ 沒有紅色錯誤訊息，程式大小約 35 KB（6%）。
   - 上傳方式是把程式複製到板子模擬出來的隨身碟 NOD_G474RE。
6. 打開「工具 → 序列埠監控視窗」，右下角選 **115200 baud** 和 **Newline**，再按板子上**黑色的 RESET 鍵**。
   - ✅ 看到 `EV,1,BOOT,1*91`，這是開機訊息。
   - Nucleo 打開序列埠時不會自動重開機（Uno 會），所以要自己按 RESET 才會看到。
7. 在輸入框打 `PING,0`，按 Enter。
   - ✅ 回 `PONG,0,1,1,…`。兩個 1 是協定版本和韌體版本，最後的數字是開機後經過的毫秒數。
   - 也可以試試以下指令。每行第二個欄位一律打 0。

     | 輸入           | 意思                | 正常回應                               |
     | -------------- | ------------------- | -------------------------------------- |
     | `STAT,0`       | 查目前狀態          | `ST,0,…`                               |
     | `AIM,0,1500,0` | 轉到俯仰 15.00°     | 還沒歸零時回 `NAK,0,7`（7 = 還沒歸零） |
     | `ZERO,0,0,0`   | 把現在的姿勢設成 0° | `ACK,0,0`                              |

     歸零之後再打一次 `AIM,0,1500,0`，會回 `ACK,0,0`。

8. **關掉序列埠監控視窗**，按一下 RESET，然後在終端機執行：

   ```bash
   python -m tools.mcu_link_test --port COM5
   ```

   - ✅ 最後一行 `FAIL 0`，PASS 大約 12 項。
   - SKIP 的有三種：要動馬達的、只有模擬器能測的，以及開機訊息那一項。最後這項 SKIP 是因為 Nucleo 開埠不會重開機。
   - 板子上**還沒接任何馬達**的話，可以加 `--allow-motion` 再跑一次，應該是 `FAIL 0`、PASS 約 18 項。
     這時腳位會送出訊號，但沒有東西會動。

## 2. 接線（給硬體組，接馬達之前看）

Nucleo 有兩種排針：

- 和 Arduino Uno 同位置的 CN5、CN6、CN8、CN9，下表寫成 D4、A3 這種名稱。
- 板子兩側的長排針 CN7、CN10，下表寫成 CN10-28，意思是 CN10 第 28 腳。

括號內是 STM32 腳位名稱。

**CN7、CN10 怎麼數**（板子 USB 那端朝左、CN10 在上方時）：

- **最準的方法是看板子背面**：每支腳旁邊都印了編號，方形焊墊是第 1 腳。
  - 翻回正面時左右會鏡像，但「外排 = 板子邊緣那排」不會變。
- 每條排針是 2 排 × 19 支。第 1、2 腳在 USB 那一端，往另一端數。
- 第 n 腳在從 USB 端數來第 ⌈n/2⌉ 列。例如第 28 腳在第 14 列、第 27 腳也在第 14 列。
- CN10：單數腳在內排（靠 Arduino 母座那排），雙數腳在外排（板子邊緣）。
  - 所以 CN10-28 是外排、從左數第 14 支。和它同一列的內排是 CN10-27，接到 D5。
- CN7：雙數腳在內排（靠 Arduino 電源和 A0–A5 母座那排），單數腳在外排。
- 數完用三用電表的導通檔對一下：
  - CN10 外排第 10 支（CN10-20）和 CN7 外排第 10 支（CN7-19）都是 GND。
  - CN10-27 和 D5 母座相通。

### 2-1 轉台步進馬達（TMC2209）

| 排針                 | 接到                                   |
| -------------------- | -------------------------------------- |
| D4 (PB5) / D7 (PA8)  | 水平 TMC2209 的 STEP / DIR             |
| D8 (PA9) / D12 (PA6) | 俯仰 TMC2209 的 STEP / DIR（兩顆並聯） |
| A3 (PB0)             | 所有 TMC2209 的 EN（LOW = 通電）       |

俯仰有兩顆步進馬達：

- 每顆各接一顆 TMC2209，兩顆的 STEP、DIR、EN 並聯，接到 D8、D12、A3。
- 兩顆馬達裝成面對面（鏡像）時，把其中一顆的一組線圈（A1、A2）對調，兩顆才會往同一邊轉。

**水平用 DRV8825（紫色小板）時**（STEP、DIR、EN 和上表一樣，EN 也是 LOW = 通電，韌體不用改）：

| DRV8825 腳 | 接到 |
| --- | --- |
| RST、SLP | 都接 Nucleo 3.3 V |
| M2 / M0、M1 | M2 接 3.3 V，M0、M1 不接 = 16 微步 |
| FAULT | 不接 |
| VMOT、GND | 電池 + 接 VMOT、− 接 GND（接反會燒，對照板子上印的字），電壓 8.2–45 V。靠近板子並一顆 47 µF 以上（建議 100 µF）電解電容：耐壓 ≥ 35 V，外殼有白色條紋那腳（負極）接 GND，接反或耐壓不夠會爆開起火。GND 和 Nucleo 共地 |
| A1、A2 / B1、B2（有的板子印 1A、1B / 2A、2B） | 馬達 A 那對線 / B 那對線 |

- 水平馬達是 42 型、機身 60 mm，對應賣場規格表的 42BYGH60：
  - 1.8°（200 步/圈）、1.5 A/相、保持力矩 0.80 N·m、1.8 Ω/相、7 mH/相、4 線。
- 接線前用電表確認 A、B 兩對：同一對之間約 1.8 Ω，不同對之間不通。
  - 賣場圖是黑綠一對、紅藍一對。換過線材的話顏色可能不一樣，以電表量到的為準。
- 電流上限 = Vref × 2（Vref = 電位器和 GND 之間的電壓）。DRV8825 沒有散熱片時最多 1.5 A。
  - 先調到 Vref 0.6 V（1.2 A，額定的 80%）。
  - 會掉步再調到 0.75 V（1.5 A），這時建議加散熱片。
- **通電時不要插拔馬達線**，DRV8825 會燒掉。
- 第一次接電池前：
  - 用電表確認 VMOT 對 GND 沒有短路（蜂鳴檔不響）。
  - 電池到驅動板串一顆保險絲（例如 3 A，比驅動板最大的 1.5 A/相大一點）。
  - 杜邦線、麵包板接不住電池短路的電流，電池線要用夠粗的線、鎖端子。
  - 還沒有電容時不要接電池，改用有限流的電源供應器測（12 V、限流 1.5 A），電源線越短越好。

**測水平（俯仰照做，把 `yaw` 換成 `pitch`）**：轉台的線要留夠長，第一次只轉 5°。

0. 馬達還沒裝上轉台時，先確認微步設定：
   - 軸上貼一條膠帶，跑 `python -m tools.turret_check --port COM5 --axis yaw --deg 72`。
   - 軸要剛好轉 1 圈：44.44 步/度 × 72° = 3200 步 = 200 步 × 16 微步。
   - 轉 2 圈或半圈，代表微步設定不是 16。
1. 韌體假設每圈 3200 個脈衝（200 步 × 16 微步）、行星減速 5:1，也就是每度 44.44 步。
   - 馬達到轉台的減速比不是 5:1 時，`YAW_STEPS_PER_DEG` 改成 3200 × 減速比 ÷ 360。例如直接驅動（1:1）是 8.89。
   - 第 3 步量出來的角度會再修正一次。
2. 看方向：

   ```bash
   python -m tools.turret_check --port COM5 --axis yaw --deg 5
   ```

   - 正值應該往右轉，從上面看是順時針。
   - 方向相反：把 `hal_arduino.h` 的 `YAW_DIR_INVERT` 改成 1，重新燒錄。
   - 馬達只抖不轉，或 10 s 內沒停：檢查 STEP、DIR、EN 的接線和馬達電源。
3. 量每度幾步：在轉台貼一根指針，底座畫一條 0° 線。

   ```bash
   python -m tools.turret_check --port COM5 --axis yaw --deg 90 --hold 10
   ```

   - 停住的 10 秒內用量角器量實際轉了幾度（θ）。
   - 工具最後會印出公式：`YAW_STEPS_PER_DEG` 改成 44.44 × 90 ÷ θ，重新燒錄後再量一次。
4. 重複精度：槍管綁雷射筆。

   ```bash
   python -m tools.turret_check --port COM5 --axis yaw --deg 30 --cycles 20
   ```

   - 看 6 m 外牆上的光點，回到 0° 的那 20 次散開要 ≤ 2 cm（約 0.2°）。

### 2-2 車輪：四顆編碼器馬達（BTS7960）

每顆馬達接一片 BTS7960 模組。PWM 和編碼器都要接在有計時器（TIM）功能的腳。

| 馬達    | 模組 RPWM      | 模組 LPWM      | 編碼器 A      | 編碼器 B     |
| ------- | -------------- | -------------- | ------------- | ------------ |
| M1 左前 | CN10-28 (PB14) | CN10-26 (PB15) | A5 (PC0)      | A4 (PC1)     |
| M2 左後 | CN10-4 (PC6)   | D11 (PA7)      | D10 (PB6)     | CN7-21 (PB7) |
| M3 右前 | CN10-2 (PC8)   | CN10-1 (PC9)   | A0 (PA0)      | CN7-3 (PC12) |
| M4 右後 | CN10-18 (PB11) | CN10-12 (PA12) | CN10-22 (PB2) | CN7-35 (PC2) |

- 用到的計時器：
  - 編碼器：M1 到 M4 依序用 TIM1、TIM4、TIM5、TIM20 的 encoder mode。
  - PWM：M1 用 TIM15，M2 用 TIM8 和 TIM17，M3 用 TIM8，M4 用 TIM2 和 TIM16。
  - TIM2、TIM3 留給 D5、D6、D9（摩擦輪、推彈，見 2-3），所以編碼器不用它們。
  - 同一顆馬達的 A、B 要接在同一個計時器的 CH1、CH2，**不能換到別的腳**。換腳要先問我。
- 四片模組共用的線：
  - **每片模組的 R_EN、L_EN 兩支都接到同一條「EN 線」，這條線接 CN10-16 (PB12)；再用一顆 10 kΩ 電阻從這條線接到 GND。**
    - R_EN、L_EN 都不能直接接 GND：兩支都是 HIGH 馬達才轉得動，任一支接地馬達就不會轉。
    - 2-3 的摩擦輪、推彈模組，以及 2-4 的 TB6612 STBY，也接到這同一條線。

    ```text
    M1 R_EN ─┐
    M1 L_EN ─┤
    M2 R_EN ─┤
    …       ─┼──── CN10-16 (PB12)
    M4 L_EN ─┤
             │
          [10 kΩ]
             │
            GND
    ```

    - 實際接法：每片模組先把自己的 R_EN、L_EN 短接，再各拉一條線到同一個接點（端子台或麵包板同一排），接點接 CN10-16 和 10 kΩ 電阻。
    - LOW = 所有馬達斷電。MCU 開機中、重開機、或韌體還沒控制這支腳時，電阻會把 EN 拉低，馬達不會突然轉。
  - VCC 接 Nucleo 的 3.3 V（CN6 第 4 腳或 CN7-16），**不要接 5 V**。
    - 模組上有一顆 74HC244 緩衝晶片。它用 4.5 V 供電時，輸入要 3.15 V 以上才保證算 HIGH，5 V 供電時門檻更高；Nucleo 的 3.3 V 訊號不夠保險。
    - VCC 改接 3.3 V 後，74HC244 送給 BTS7960 的訊號是 3.3 V；BTS7960 晶片的 HIGH 門檻最高約 2.15 V，夠用。
  - GND 接 Nucleo 的 GND。
  - R_IS、L_IS（電流偵測）不接。
- 每片模組的電源與馬達：
  - B+、B− 接馬達電池，要經過紅色急停開關。
  - M+、M− 接馬達的兩條電源線。
- 編碼器（JGB37-520，12 V 178 rpm，每轉 11 脈衝、減速比 1:56）：
  - VCC 接 3.3 V，GND 接 GND。
  - ⚠️ 11/04 實測：VCC 3.3 V 時 A 只在 2.7 V ↔ 2.4 V 之間變，Nucleo 讀不到（要低於約 1 V 才算 LOW），可能要 5 V 供電。
  - **不要四顆一起改 5 V**：PC1（M1 B）、PA0（M3 A）、PB2（M4 A）是 TT 腳，最高只能 4.0 V（DS12288 表 14）。
    只有 M2 的 PB6、PB7 能直接接 5 V 訊號。改法等軟體組確認。
  - 編碼器的線不要和馬達電源線綁在一起走，減少雜訊。
- 韌體已經支援，要重新燒錄（第 1 步）。
- 輪子是麥克納姆輪：
  - 麥克納姆輪分左旋、右旋兩種。**對角線的兩顆要用同一種**：左前和右後一樣，右前和左後一樣。
  - 操控台已經照麥克納姆輪混控：可以前後、左右平移、原地轉。設定在 `configs/field.yaml` 的 `chassis`。

### 2-3 摩擦輪、推彈（建議用 BTS7960，現在的韌體就能控制）

這三顆都只往一個方向轉，每顆接一片 BTS7960，只用 RPWM：

| 馬達     | 模組 RPWM | 模組 LPWM |
| -------- | --------- | --------- |
| 左摩擦輪 | D5 (PB4)  | 接 GND    |
| 右摩擦輪 | D6 (PB10) | 接 GND    |
| 推彈     | D9 (PC7)  | 接 GND    |

- R_EN、L_EN 也接到 2-2 那條共用 EN 線（CN10-16），VCC 接 3.3 V、GND 接 GND，和車輪一樣。
- 轉的方向反了：對調那顆馬達的 M+、M−。
- 測摩擦輪（不放球、手和線遠離輪子）：
  1. 低速：`python -m tools.fly_check --port COM5 --rpm 600 --seconds 5`（PWM 約 20%）。
  2. 看兩個輪子的方向：貼著球的那一面，要一起往「出球方向」轉。不對就對調那顆的 M+、M−。
  3. 方向對了再加速：`python -m tools.fly_check --port COM5 --rpm 2400 --seconds 5 --ramp 2`（6 m 的設計轉速）。
  - 沒有轉速計，畫面上的「量測」會顯示「無轉速計」；改目標後 1.5 秒「到速」才會變成「是」。
  - 隨時可以按 Ctrl+C，工具會送出停止。
- BTS7960 最大 43 A，硬體組確認電流夠用。

選配：

| 排針         | 接到                                                                 |
| ------------ | -------------------------------------------------------------------- |
| CN7-1 (PC10) | 推彈原點開關（原本在 A0，A0 改給 M3 編碼器）                         |
| A2           | 電池分壓（建議接，見下方說明）                                       |
| A1           | 急停輔助接點                                                         |

- 摩擦輪馬達沒有編碼器，轉速是開迴路，電池電壓下降時轉速會跟著掉。
- 建議接 A2 的電池分壓，讓韌體依電壓補 PWM。原本留給轉速計的 D2、D3 改給彈倉開關用。

### 2-4 彈倉：6 顆 N20 直流減速馬達 + 微動開關

每顆馬達只往同一個方向轉，轉到微動開關被壓下就停。

**驅動板：TB6612FNG 模組 × 3**（一片帶兩顆馬達）

- 規格：馬達電壓 2.5–13.5 V，每路平均 1.2 A（有些版本寫 1.0 A），邏輯電壓 2.7–5.5 V，可以直接吃 3.3 V。
- N20 是小馬達，推測堵轉電流在 1 A 以內。拿到馬達規格請確認堵轉電流小於 1 A。

| 彈倉 | 馬達（接 TB6612 的 PWMA / PWMB） | 微動開關 |
| ---- | -------------------------------- | -------- |
| 1    | CN10-14 (PA11)                   | CN7-2 (PC11) |
| 2    | CN10-30 (PB13)                   | CN7-4 (PD2)  |
| 3    | CN10-24 (PB1)                    | D1 (PC4)     |
| 4    | D14 (PB9)                        | D0 (PC5)     |
| 5    | CN7-37 (PC3)                     | D2 (PA10)    |
| 6    | D13 (PA5)                        | D3 (PB3)     |

- TB6612 每一路（A、B 各一路）的接法：
  - IN1 接 3.3 V，IN2 接 GND。只轉一個方向，所以 IN1、IN2 固定。
  - PWM 接上表的腳：HIGH = 轉，LOW = 煞車。
  - 馬達接 O1、O2；方向反了就對調這兩條。
- 每片 TB6612 共用的線：
  - STBY 接 2-2 那條共用 EN 線（CN10-16）。MCU 開機中或急停時，彈倉馬達也會停。
  - VCC 接 3.3 V，GND 接 GND。
  - VM 接馬達電源。電壓要符合 N20 的規格，而且不能超過 13.5 V。
- 彈倉 6 的馬達接在 D13，板子上的綠色 LED 也接在這支腳，所以那顆馬達轉的時候 LED 會亮。這是正常的。
- 微動開關：
  - 建議用小型、帶滾輪的槓桿式微動開關，例如 Omron SS-5GL2，或常見的 KW11-3Z 滾輪型。
  - 在轉動的零件上做一個凸塊，每轉到一格就壓下開關一次。
  - 開關有三支腳，只用 COM 和 NO：COM 接 GND，NO 接上表的腳。韌體會開內部上拉，壓下 = LOW。
  - 開關線和 GND 線絞在一起走，不要和馬達電源線綁在一起。
- 彈倉的韌體還沒寫。動作順序確定後我再寫（見最後的問題），先接線不會動。
- 腳位幾乎用完了，只剩 PC13（板上藍色按鈕）和 PA15（要看焊橋）。之後再加東西要先問我。

**Nucleo 的腳位是 3.3 V，不是 Uno 的 5 V：**

- TMC2209 的 VIO 接板子的 3.3 V。
- 兩顆 TMC2209 的 MS1、MS2 都接 3.3 V，設成 16 微步，韌體是照 16 微步算角度的。
  兩隻都接地時是 8 微步，轉台會轉成指令角度的 2 倍。
- BTS7960 模組、編碼器、TB6612 的 VCC 接 3.3 V（見 2-2、2-4）。
- 開關和感測器只接到 GND。韌體已經打開內部上拉，不要把 5 V 直接接進腳位。
- 電池分壓用 47 kΩ / 10 kΩ（3S 滿電 12.6 V 會變成 2.2 V）。
  ADC 參考電壓要量 CN5 第 8 腳（VREFP），把量到的數字填進 `config.h` 的 `VBAT_ADC_VREF`。

其他設定：

- 腳位、每度幾步、角度上下限、車輪方向都寫在 `firmware/rotbot_mcu/config.h`，改完要重新上傳。
- **第一次接馬達時**，飛輪不要放球，發射口前面不要站人，然後執行：

  ```bash
  python -m tools.mcu_link_test --port COM5 --allow-motion
  ```

  - ✅ 結果是 `FAIL 0`。
  - 轉的方向相反：把 `hal_arduino.h` 的 `PITCH_DIR_INVERT` 或 `YAW_DIR_INVERT` 改成 1。
  - 轉的角度不對：先確認上面的微步設定，再改 `config.h` 的 `PITCH_STEPS_PER_DEG` 或 `YAW_STEPS_PER_DEG`。
- **第一次接車輪時**，先把車架高、四個輪子離地，然後執行：

  ```bash
  python -m tools.mcu_link_test --port COM5 --allow-drive
  ```

  - 四個輪子會依序 M1 → M4 各往前轉 1 秒（30% 輸出）。
  - ✅ 「車輪逐輪轉 + 編碼器」那行是 PASS，四個數字都是正的。
  - 輪子往後轉：`config.h` 的 `WHEEL_INVERT` 把那顆馬達的位元反過來（M1 = 1、M2 = 2、M3 = 4、M4 = 8，預設 12 = M3 + M4）。
  - 輪子往前轉但數字是負的：改 `WHEEL_ENC_INVERT` 的同一個位元。
  - 轉的是 M1，數字卻出現在別的馬達：那兩顆的編碼器線接錯了。
  - 數字全是 0：用 `python -m tools.wheel_check --port COM5` 一顆一顆查（下面「車輪全是 0 怎麼查」）。
- **車輪全是 0 怎麼查**（一次查一顆）：
  1. 用手轉輪子，不用開馬達電源：`python -m tools.wheel_check --port COM5`。
     - 那顆的數字有變：編碼器正常，往下一步。
     - 一直是 0：查編碼器的 VCC（3.3 V）、GND，以及 A、B 是不是接在表上那兩支腳。
  2. 車架高、開馬達電源，只轉一顆：`python -m tools.wheel_check --port COM5 --spin M1 --duty 0.4 --seconds 3`。
     - 輪子沒轉：用三用電表量模組的 VCC（應該 3.3 V）、R_EN 和 L_EN（程式跑起來後應該 3.3 V）、B+/B−（電池電壓）；再確認 RPWM、LPWM 接在表上那兩支腳。
     - 輪子有轉、數字是 0：回到第 1 步查編碼器。
  3. 編碼器還是 0：`python -m tools.wheel_check --port COM5 --raw`，用手慢慢轉輪子，看那顆的「A B」兩個數字。
     - 會在 0、1 之間跳，但後面的計數不動：韌體的問題，把輸出給軟體組。
     - 一直是 `1 1`：訊號沒有進到 Nucleo。查編碼器的 VCC、GND 有沒有電，A、B 線有沒有接到表上的腳。
- **四輪都正確之後，車子放地上**，用操控台手動開（第 6 步的按鍵），依序試：
  1. ↑：車子往前直走。
  2. `<` `>`：原地轉。如果轉不太動、輪子在打滑，代表左旋、右旋的輪子裝反了，要把左右兩側的輪子對調。
  3. ← →：往左、右平移。方向反了就把 `field.yaml` 的 `chassis.strafe_invert` 改成 `true`。

## 4. 量出球速（等飛輪做好）

- 在離牆 2 m、4 m、6 m 三個距離各打約 10 球，記下每一球的落點，存成 CSV。
  每一行是：距離、仰角、水平角、落點橫向位置、落點離地高度（單位：公尺、度）。
- 執行：

  ```bash

  ```

  - ✅ 會印出出球速度 v0，以及一段要貼進 `configs/field.yaml` 的數字。
  - 貼進去以後，AI 瞄準和操控台的預估落點都會改用實測值。
  - 只打兩個距離的話，速度和空氣阻力會分不開，所以三個距離都要打。

## 6. 整台機器人

1. Jetson 只要準備一次：
   - numpy 和 OpenCV 用 JetPack 內建的（numpy 1.21、OpenCV 4.8）。**不要裝 `requirements.txt`**，它會把這兩個換成新版。
   - 依序執行：

     ```bash
     pip3 install -r requirements-jetson.txt
     # 這裡裝 NVIDIA 給 JetPack 6 的 PyTorch 和 torchvision
     pip3 install --no-deps ultralytics==8.4.188
     ```

     ultralytics 一定要加 `--no-deps`，不加的話它也會把 numpy 和 OpenCV 換掉。

   - ✅ 執行下面這行，印出的三個值依序是 `1.21` 開頭、`4.8` 開頭、`True`（GPU 可用）：

     ```bash
     python3 -c "import numpy, cv2, torch; print(numpy.__version__, cv2.__version__, torch.cuda.is_available())"
     ```

   - 把 `models/grid_holes_yolo11n.pt` 複製過去。模型權重不在 git 裡。
   - 序列埠權限：`sudo usermod -aG dialout $USER`，重新登入才生效。Nucleo 接上 Jetson 會是 `/dev/ttyACM0`。

2. 在 Jetson 上執行 `python3 -m tools.robot_main --mcu /dev/ttyACM0`，相機會自動用 IMX296。
3. 筆電或手機連同一台路由器，打開它印出來的網址（`http://192.168.x.x:8080`）。
   - 用搖桿時不能直接開 IP，瀏覽器會擋搖桿。筆電先執行 `ssh -N -L 8080:127.0.0.1:8080 ben-orin@192.168.50.10`（視窗開著），再開 `http://localhost:8080`。
4. 開始前，先把轉塔擺到「槍管水平、正對前方」，然後按「歸零」。
5. 按「開始」就等於哨音：前 60 秒 AI 自己投，之後可以按「切手動」。
6. 手動時看畫面上的圈：**綠圈 = 這一球會進，橘圈 = 不會進。**
   右下角的小圖是整面網板，瞄高處時網板會跑出畫面，就看小圖。
   - 開車：↑↓ 前後、←→ 左右平移、`<` `>` 原地轉；搖桿是左搖桿前後和平移、十字鍵左右原地轉。
   - 瞄準：W/S/A/D，或搖桿的右搖桿。
   - 放開按鍵、網頁斷線或切走視窗，車子都會停。
7. 畫面上方出現紅色的「MCU 重開機」警告時：
   - 程式已經自動補回歸零，也重送了轉塔目標和飛輪轉速，比賽照常進行，不用按任何鍵。
   - 賽後檢查 USB 線和電源，按「重置」警告就會消失。
   - 警告寫「無法自動補回」，代表重開機前沒按過歸零。這時要回待命，擺好姿勢重新歸零。

## 7. 比賽前（練習日）

1. 在場地做一次第 4 步，更新 `configs/field.yaml`，並存好 `runs/calib/practice.json`。
2. 比賽時帶著這個校正檔啟動：

   ```bash
   python3 -m tools.robot_main --mcu /dev/ttyACM0 --calib runs/calib/practice.json
   ```

3. 從練習到比賽，飛輪轉速要穩定，誤差在 1% 以內。轉速漂掉的話，練習學到的校正會變得不準。
